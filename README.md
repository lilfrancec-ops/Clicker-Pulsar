# 🛰 Космокликер: Пульсар

Браузерный космический кликер/идлер: вы управляете станцией вокруг аномального пульсара,
добываете звёздную энергию, строите орбитальные станции, запускаете дроны, переживаете
космические события, открываете достижения и в итоге выполняете **Коллапс Сингулярности**
(престиж), чтобы начать цикл заново с постоянными бонусами.

Стек: **HTML5 + CSS3 + Vanilla JavaScript (ES Modules) + Firebase Web SDK**.
Никаких фреймворков, сборщиков и собственного бэкенда.

---

## 1. Как запустить

Firebase modular SDK использует ES-модули, поэтому `index.html` **не откроется через `file://`**.
Нужен любой статический сервер.

### Вариант A — свой dev-сервер из репозитория (0 зависимостей)

```bash
node tools/dev-server.mjs        # http://localhost:5173
# или
npm run dev
```

### Вариант B — `npx serve`

```bash
npx serve . -l 5173
```

> В PowerShell `npx` может быть заблокирован политикой выполнения. Тогда:
> `npx.cmd serve . -l 5173` или используйте Вариант A.

### Вариант C — preview в OpenCode / Firebase App Hosting / GitHub Pages

Проект статический: подходит любой хостинг, отдающий файлы по HTTPS.
Для Firebase App Hosting достаточно добавить в корень, например:

```json
{ "hosting": { "public": "." } }
```

### Настройка Firebase (обязательно для облачного режима)

1. **Firebase Console → Authentication → Sign-in method → Anonymous → Enable**
2. **Authentication → Settings → Authorized domains** → добавить `localhost` и домен хостинга
3. **Firestore Database → Create database** (production mode)
4. Применить правила из [firebase.rules.md](./firebase.rules.md)
   (Firebase Console → Firestore Database → Rules → Publish)

> **Важно:** если пункты 1–3 не сделаны, игра всё равно работает — она автоматически
> переходит в локальный режим и показывает понятное объяснение в тостах и в панели
> «☁️ Облако».

### Принцип разделения

| Слой | Отвечает | Не делает |
|---|---|---|
| Данные (`upgrades.js`, `buildings.js`, …) | цифры баланса и тексты | ничего |
| `formulas.js` | математику (чистые функции) | не меняет состояние |
| `state.js` | форму и безопасность данных | не знает о Firebase |
| `ui.js` | DOM и события интерфейса | не знает правил игры |
| `game.js` | связывает всё вместе | не знает, как устроен Firestore |
| `saveManager.js` | стратегию сохранений | не знает о формулах |

## 3. Механики

### Ресурсы

| Символ | Ресурс | Откуда |
|---|---|---|
| ⚡ | Звёздная энергия | клики, постройки, события, оффлайн-доход, автоклик |
| ◈ | Квантовые ядра | достижения (шанс за клик), метеориты, золотая комета |
| ✦ | Осколки Сингулярности | Коллапс Сингулярности (престиж) |

### Цикл игры

1. Клик по пульсару → энергия, всплывающее число, волна, искры, звук.
2. Покупка улучшений клика и построек → рост силы клика и дохода в секунду.
3. Разовые технологии (вкладка «Технологии») меняют правила: ×2 к клику, автоклик,
   спутниковая синхронизация, квантовая запутанность, хроностазис, протокол сингулярности.
4. Случайные события (раз в 3–8 минут): метеоритный дождь, золотая комета, квантовая флуктуация.
5. Активные способности с перезарядкой: Сверхновая, Замедление времени,
   Гравитационная линза, Рой дронов.
6. Достижения дают постоянные бонусы (+1…+10% к множителям, шанс ядер).
7. Коллапс Сингулярности → осколки ✦ → престижные улучшения → более быстрый следующий цикл.

### Ключевые формулы

```js
// Стоимость (экспоненциальный рост)
cost = ceil(baseCost * growth^owned)

// Сила клика
clickPower = (base + Σ(улучшения клика) + бонусы за постройки)
             × манипуляторы(×2) × globalMultiplier × (1 + бонусы достижений) × combo

// Автоматический доход
autoPerSecond = Σ(count × production × спец-множители)
                × globalMultiplier × (1 + бонусы) × timeDilation(×2)

// Глобальный множитель
globalMultiplier = (1 + resets × 0.25 + achievementBonus) × prestigeMultiplier

// Оффлайн
offlineSeconds = min((now - lastSave)/1000, 2 ч)
offlineGain    = autoPerSecond × offlineSeconds × efficiency   // 50% (100% с Хроностазисом)

// Престиж
prestigeGain = floor(sqrt(runLifetime / 1 000 000) × (1 + 0.1 × fastSingularity))
```

> **Важно про `lifetimeEnergy` и `runLifetime`.** В состоянии хранятся два счётчика:
> `lifetimeEnergy` — энергия за всё время (достижения, лидерборд) и
> `runLifetime` — энергия за текущий цикл (именно она даёт осколки за Коллапс).
> Иначе повторные сбросы приносили бы бесплатные осколки.

## 4. Как добавить новый контент

Все элементы игры описаны **данными**, UI строится из них автоматически.

### Новое улучшение клика

Добавьте объект в `CLICK_UPGRADES` (`js/upgrades.js`):

```js
{
  id: "flux_coils",
  name: "Катушки потока",
  description: "+2 энергии за клик",
  type: "click",          // click | click_chance | crit | combo | click_from_buildings
  value: 2,
  baseCost: 5000,
  growth: 1.25,
  icon: "🧲"
}
```

Новый `id` автоматически попадёт в `state.upgrades`, будет сохранён в сейв
и отрисован в магазине. Ничего в UI менять не нужно.

### Новая постройка

Добавьте объект в `BUILDINGS` (`js/buildings.js`) с полями
`id, name, description, production, baseCost, growth, icon`.

### Новая разовая технология / способность / событие / достижение

Аналогично добавляются в `ONE_TIME_UPGRADES`, `ABILITIES`, `EVENTS`, `ACHIEVEMENTS`.
Условия доступности описываются декларативно:

```js
requires: { buildings: { orbital_shipyard: 1 } }   // или upgrades: {...}, lifetimeEnergy: N
```

Для достижения достаточно написать функцию `check(state)`.

### Как поменять баланс

* Стоимость/продажа/рост — в массивах данных (`js/upgrades.js`, `js/buildings.js`).
* Глобальные лимиты и интервалы — `js/config.js`:
  `baseClickPower`, `offlineCapSeconds`, `offlineEfficiency`,
  `localAutosaveMs`, `cloudSaveMinIntervalMs`, `prestigeDivisor`, `eventMinGapMs`.
* Формулы — только в `js/formulas.js` (нигде больше нет «магических» множителей).

## 5. Firebase

Используются **только два** продукта Firebase:

| Продукт | Зачем |
|---|---|
| **Firebase Authentication** | анонимный вход, чтобы получить `uid` |
| **Cloud Firestore** | облачное сохранение прогресса и публичный лидерборд |

`apiKey` в клиенте **не является секретом** — доступ ограничивается списком
Authorized domains в консоли проекта. В коде нет сервисных аккаунтов и приватных ключей.

### 5.1 Анонимная авторизация

Поток в `js/auth.js`:

1. `initFirebase()` динамически импортирует модульный SDK с `gstatic` (10.14.1).
2. Включается `browserLocalPersistence`, чтобы анонимный пользователь переживал перезагрузку.
3. `onAuthStateChanged` следит за пользователем.
4. Если пользователя нет → `signInAnonymously()`.
5. Полученный `uid` используется как ключ `users/{uid}` и `public/leaderboard/{uid}`.
6. Любая ошибка не ломает игру: статус становится «Локально» или «Ошибка»,
   прогресс продолжает сохраняться в `localStorage`.

Статусы в интерфейсе: `Подключение…` → `Облако подключено` / `Локально` / `Ошибка`.

Обрабатываются и показываются человеческим текстом:
`auth/unauthorized-domain`, `auth/network-request-failed`, `auth/operation-not-allowed`,
`auth/too-many-requests`, `auth/configuration-not-found`.

Кнопка «🔌 Повторить подключение» в панели сохранения перезапускает попытку.

### 5.2 Облачное сохранение

`users/{uid}`:

```jsonc
{
  "version": 1,
  "createdAt": <serverTimestamp>,   // проставляется при первом сохранении (merge: true)
  "updatedAt": <serverTimestamp>,   // служебное поле
  "savedAt": 1757000000000,         // число: ключ для разрешения конфликтов
  "energy": 0,
  "lifetimeEnergy": 0,              // за всё время (достижения, лидерборд)
  "runLifetime": 0,                 // за текущий цикл (престиж)
  "totalClicks": 0,
  "crystals": 0,
  "prestigeShards": 0,
  "upgrades": { "click_gloves": 0 },
  "buildings": { "orbital_collector": 0 },
  "oneTimeUpgrades": [],
  "achievements": [],
  "prestige": { "resets": 0, "gained": 0, "upgrades": {} },
  "stats": { "runClicks": 0, "eventsTriggered": 0, "cloudSaves": 0, "bestEps": 0, "lastPrestigeAt": 0 },
  "settings": { "animations": true, "sound": true, "confirm": true, "numbers": true },
  "lastSave": 1757000000000         // для оффлайн-дохода
}
```

`public/leaderboard/{uid}`:

```jsonc
{
  "name": "Пульсар-ab12",
  "lifetimeEnergy": 12345678,
  "prestigeShards": 42,
  "resets": 3,
  "updatedAt": <serverTimestamp>
}
```

**Что никогда не сохраняется:** временные баффы и перезарядки способностей,
DOM-узлы, функции, `NaN`, `Infinity`, `undefined`, логи, секреты.
Сериализация выполняется **явно** в `state.serializeState()`, нормализация входа —
в `state.normalizeState()`: неизвестные `id` отбрасываются, значения округляются и
приводятся к валидным числам.

### 5.3 Локальное сохранение

Ключ: **`cosmic_pulse_clicker_save_v1`**. Структура совпадает с облачной,
добавляется `localUpdatedAt: Date.now()`. Если `localStorage` недоступен
(приватный режим), используется память вкладки — игра не падает.

### 5.4 Разрешение конфликтов сохранений

`saveManager.resolveConflict(local, cloud)` — чистая функция:

| Ситуация | Выбор | Тост |
|---|---|---|
| нет обоих | новое состояние | — |
| только облако | облако | «Загружено облачное сохранение» |
| только локальное | локальное | «Загружено локальное сохранение» |
| `cloudUpdatedAt > localUpdatedAt` | облако | «Конфликт сохранений: облако было свежее» |
| `localUpdatedAt > cloudUpdatedAt` | локальное | «Конфликт сохранений: выбран более свежий прогресс» |
| времена равны | больше `lifetimeEnergy` | «Конфликт сохранений…» |
| времена и `lifetimeEnergy` равны | облако | «Конфликт сохранений…» |

Если выбрано локальное сохранение, а облако доступно — прогресс сразу уходит в облако.

### 5.5 Автосохранение

**Локально:** каждые 5 секунд (если есть изменения), при покупке, престиже, сбросе,
изменении настроек, при скрытии вкладки и закрытии (`pagehide` / `beforeunload`).

**В облако:** схема `markDirty() → scheduleCloudSave() → flushCloudSave()`.

* не чаще одного раза в 8 секунд (обычный сценарий);
* «немедленно» (в пределах 2 секунд) для важных событий: покупка, престиж, сброс, настройки;
* при ошибках записи интервал растёт до 60 секунд — защита от квоты;
* `cloudSave` получает **снапшот** состояния, а не каждое микроизменение;
* при `pagehide` отправка запускается «fire and forget» и не блокирует закрытие вкладки.

Кнопки в панели «☁️ Облако»: сохранить локально, сохранить в облако, загрузить из облака
(с подтверждением, если данные отличаются), синхронизировать, повторить подключение,
сбросить прогресс, загрузить рейтинг.

### 5.6 Firestore Security Rules

См. отдельный файл **[firebase.rules.md](./firebase.rules.md)** — там есть полные
и минимальные правила, проверка через эмулятор и список обязательных настроек консоли.

Коротко:

* `users/{userId}` — читать и писать может только владелец `uid`;
* `public/leaderboard/{userId}` — читать могут все, писать — только владелец, и только
  разрешёнными полями;
* всё остальное запрещено (`allow read, write: if false`).

## 6. Производительность и адаптивность

* Игровой цикл — `requestAnimationFrame` с `dt` из реального времени,
  `dt` ограничен 1 секундой, поэтому после возврата во вкладку не будет скачков.
* HUD обновляется ~12 раз/сек, магазин ~4–5 раз/сек, а не каждый кадр.
* Элементы магазина создаются один раз; обновляется только текст
  (`setText` сравнивает строку и ничего не делает, если текст не изменился).
* Всплывающие числа, искры и волны удаляются из DOM по `animationend` + страховка по таймеру;
  количество частиц ограничено (не более 60 искр, 8 волн, 5 тостов).
* Анимации — только `transform`/`opacity`.
* Звёздный фон рисуется на `<canvas>` (~40–220 звёзд) и останавливается вместе с анимациями.
* `prefers-reduced-motion: reduce` и переключатель «✨ Анимации» убирают движение.
* Мобильные: `viewport-fit=cover`, адаптивная сетка (на узких экранах магазин уходит
  под сцену), крупные кнопки, отсутствие горизонтального скролла,
  `touch-action: manipulation` против двойного тапа и зума на пульсаре,
  отключено выделение текста при быстрых кликах.

## 7. Доступность

* Пульсар — настоящий `<button>` с `aria-label`: работает мышью, touch и клавишами
  **Enter / Пробел**; есть `:focus-visible`.
* Статус Firebase — `aria-live="polite"`, уведомления не только цветовые
  (у каждого есть текст и символ), ошибки помечены `role="alert"`.
* Все действия — семантические кнопки с текстовыми подписями и `disabled` вместо
  «надо угадать, почему не работает».
* Lighthouse: **Accessibility 1.0**, Best Practices 1.0, SEO 1.0.

## 8. Отладка

В консоли браузера доступен объект `window.__COSMIC__`:

```js
__COSMIC__.state             // текущее состояние
__COSMIC__.runtime           // временные баффы, перезарядки, событие
__COSMIC__.api.stepSimulation(0.25)  // один шаг симуляции без requestAnimationFrame
__COSMIC__.save.getSaveMeta()         // время локального/облачного сейва, интервал записи
__COSMIC__.config                      // константы баланса
```

Полезно для проверки механик при свёрнутом окне или в headless-окружении,
где `requestAnimationFrame` может не запускаться.
